# B1 · บันทึกการแก้บั๊ก (กรอกให้ครบทั้ง 6 จุด)

> แต่ละบั๊กให้เขียน 4 อย่าง: ไฟล์ · บรรทัด · สาเหตุ (ทำไมทำงานผิด) · แก้อย่างไร
> เขียนด้วยคำของตัวเอง — จุดนี้จะถูกถามใน oral

## บั๊กที่ 1 — อาการ: Console เตือนสีเหลืองเรื่องรายการ
- ไฟล์/บรรทัด: src/components/RequestList.jsx : บรรทัดที่ 8
- สาเหตุ: การวนลูปแสดงผลรายการด้วย .map() ไม่ได้ใส่ key prop ให้กับ JSX element หรือคอมโพเนนต์ที่คืนค่าออกไป ทำให้ React แจ้งเตือนเรื่อง Unique Key
- แก้อย่างไร: เพิ่ม key={request.id || index} เข้าไปในคอมโพเนนต์ <RequestCard/> ที่อยู่ภายใน .map()

## บั๊กที่ 2 — อาการ: ตัวเลข "รอดำเนินการ" ในแผงสรุปไม่ตรงกับที่เห็น
- ไฟล์/บรรทัด: src/pages/DashboardPage.jsx : บรรทัดที่ 37
- สาเหตุ: ในฟังก์ชันคำนวณ summary ส่วนของคีย์ pending เขียนเงื่อนไขเช็กสถานะผิดเป็น request.status === 'completed' ทำให้ตัวเลขรอดำเนินการดึงจำนวนของรายการที่เสร็จสิ้นมานับแทน
- แก้อย่างไร: แก้ไขเงื่อนไขการกรองในช่อง pending จาก 'completed' ให้เป็น 'pending' ให้ตรงตามคีย์

## บั๊กที่ 3 — อาการ: กดตัวกรอง "รอดำเนินการ" แล้วได้รายการที่ไม่ใช่
- ไฟล์/บรรทัด: src/pages/DashboardPage.jsx : บรรทัดที่ 43
- สาเหตุ: ในฟังก์ชันกรองข้อมูล filteredRequests ใช้เครื่องหมายเปรียบเทียบเป็น !== (ไม่เท่ากับ) ทำให้ระบบดึงรายการที่มีสถานะ ไม่ตรง กับที่เลือกมาแสดงแทน
- แก้อย่างไร: เปลี่ยนเครื่องหมายเปรียบเทียบจาก !== เป็น === เพื่อให้กรองเฉพาะรายการที่มีสถานะตรงตามที่เลือก

## บั๊กที่ 4 — อาการ: เปลี่ยน URL จาก REQ-001 เป็น REQ-002 แล้วข้อมูลไม่เปลี่ยน
- ไฟล์/บรรทัด: src/pages/RequestDetailPage.jsx : บรรทัดที่ 18
- สาเหตุ: ใน useEffect ที่ใช้ดึงข้อมูลรายละเอียดคำร้อง ไม่ได้ใส่ requestId ไว้ใน Dependency Array ทำให้เมื่อ URL หรือพารามิเตอร์เปลี่ยน เอฟเฟกต์จึงไม่ทำงานซ้ำเพื่อดึงข้อมูลใหม่
- แก้อย่างไร: เพิ่ม requestId เข้าไปใน Dependency Array ของ useEffect เป็น [requestId]

## บั๊กที่ 5 — อาการ: กด "ลบ" แล้วรายการยังอยู่ ต้องรีเฟรชถึงหาย
- ไฟล์/บรรทัด: src/pages/DashboardPage.jsx : บรรทัดที่ 51
- สาเหตุ: ในฟังก์ชัน handleDelete มีการอัปเดต state ด้วยค่าเดิม setRequests(requests) แทนที่จะใช้ข้อมูลอาร์เรย์ใหม่ที่ลบแล้ว ทำให้ React ไม่ re-render ข้อมูลใหม่บนหน้าจอทันที
- แก้อย่างไร: ปลี่ยนการอัปเดต state ให้เป็น setRequests(nextRequests) เพื่อให้นำข้อมูลอาร์เรย์ใหม่ที่ผ่านการลบแล้วไปแสดงผลทันที

## บั๊กที่ 6 — อาการ: กด "Reset Demo Data" แล้วหน้าพัง/ว่างเปล่า
- ไฟล์/บรรทัด: ปลี่ยนการอัปเดต state ให้เป็น setRequests(nextRequests) เพื่อให้นำข้อมูลอาร์เรย์ใหม่ที่ผ่านการลบแล้วไปแสดงผลทันที
- สาเหตุ: ฟังก์ชัน handleReset เรียกใช้ resetRequests() ซึ่งเป็น asynchronous (async) หรือคืนค่าผลลัพธ์ไม่ถูกต้องตามที่ state คาดหวัง ส่งผลให้นำค่าที่ไม่ใช่อาร์เรย์ปกติไปตั้งใน setRequests
- แก้อย่างไร: เพิ่ม await หน้า resetRequests()หรือปรับแก้ให้รับอาร์เรย์รายการใหม่ที่คืนกลับมาแล้วใส่ลงใน setRequests(...) เพื่อรีเซ็ตข้อมูลให้อัปเดตอย่างถูกต้อง
