## BUG #0 · รายละเอียด 10 ตัวอักษรพอดีแต่แจ้ง Error

- **อาการ:** กรอกรายละเอียด (details) ครบ 10 ตัวอักษรพอดี แต่ระบบแจ้ง error ว่ารายละเอียดสั้นเกินไป
- **วิธีทำซ้ำ:** รัน unit test ทดสอบส่งข้อมูลที่ช่อง details มีความยาว 10 ตัวอักษรพอดี
- **เครื่องมือ:** Unit test (`npm test --prefix api`)
- **สาเหตุ (ไฟล์:บรรทัด):** `api/src/validators/requestvalidator.js` ใส่เงื่อนไขเช็คความยาวผิดพลาดโดยใช้เครื่องหมาย `<=` 
- **วิธีแก้:** เปลี่ยนเครื่องหมายในเงื่อนไขการเช็คความยาวจาก `<=` เป็น `<`
- **test ที่กัน:** `api/tests/unit/requestValidator.test.js` (เทสต์ค่าขอบรายละเอียด 10 ตัวอักษรพอดี)

## BUG #1 · ลบคำร้องแล้วเพิ่มใหม่ ได้ 500

- **อาการ:** ลบคำร้องทิ้ง 1 รายการ แล้วสร้างคำร้องใหม่ทันที ระบบจะ Error 500
- **วิธีทำซ้ำ:** ยิง `curl -X DELETE` ลบคำร้อง (เช่น REQ-002) แล้วตามด้วย `curl -X POST` สร้างคำร้องใหม่
- **เครื่องมือ:** VS Code JavaScript Debug Terminal (ตั้ง Breakpoint)
- **สาเหตุ (ไฟล์:บรรทัด):** `api/src/services/requestService.js` ฟังก์ชันหา ID ใหม่ทำงานโดยนับความยาวของ Array เมื่อข้อมูลถูกลบ ความยาวจะลดลง ทำให้สร้าง ID ซ้ำกับที่มีอยู่แล้ว
- **วิธีแก้:** เปลี่ยนวิธีคำนวณ ID ใหม่ โดยให้ดึงเลข ID จากรายการสุดท้ายใน Array มาบวก 1 แทนการใช้ความยาวรวม
- **test ที่กัน:** `api/tests/integration/requests.api.test.js` (เทสต์สร้างคำร้องหลังจากมีการลบข้อมูล)

## BUG #2 · Dashboard แสดง "กำลังดำเนินการ 0"

- **อาการ:** หน้า Dashboard ฝั่ง Frontend แสดงการ์ด "กำลังดำเนินการ" เป็นเลข 0 ทั้งที่มีข้อมูล in-progress 
- **วิธีทำซ้ำ:** เปิดหน้า Dashboard บนเบราว์เซอร์แล้วดูตัวเลขสรุปผล
- **เครื่องมือ:** DevTools (Network tab และ Sources สำหรับตั้ง Breakpoint)
- **สาเหตุ (ไฟล์:บรรทัด):** `frontend/src/utils/requestSummary.js` พิมพ์ชื่อเงื่อนไขสถานะผิด (เช่น 'in progress' ไม่มีขีดกลาง) ไม่ตรงกับที่ API ส่งมา ('in-progress')
- **วิธีแก้:** แก้ชื่อสตริงที่ใช้เช็คเงื่อนไขให้เป็น 'in-progress' ให้ตรงกับ API
- **test ที่กัน:** `frontend/src/utils/requestSummary.test.js`

## BUG #3 · เปลี่ยนสถานะคำร้องที่ไม่มีอยู่ ได้ 500

- **อาการ:** ส่งคำสั่งเปลี่ยนสถานะของ ID ที่ไม่มีอยู่จริง แล้วได้ HTTP 500 แทนที่จะได้ 404 Not Found
- **วิธีทำซ้ำ:** ยิง `curl -X PUT localhost:3001/api/requests/REQ-999` เปลี่ยนสถานะคำร้อง
- **เครื่องมือ:** อ่าน stack trace จาก Terminal
- **สาเหตุ (ไฟล์:บรรทัด):** `api/src/controllers/requestController.js` เกิด error `Cannot read properties of null` เพราะระบบไม่ได้เช็คว่าหาคำร้องเจอหรือไม่ก่อนนำไปใช้งาน
- **วิธีแก้:** เพิ่มเงื่อนไขเช็ค `if (!request) { return res.status(404).json(...); }` ก่อนอัปเดตข้อมูล
- **test ที่กัน:** `api/tests/integration/requests.api.test.js` (เทสต์ PUT ลบหรือแก้ไข ID ที่ไม่มีอยู่จริง -> 404)
